Список данных для трейсинга:
    1. UUID
    2. UserID или SystemID
    3. LogType
    4. SpanID
    5. Сообщение

Мотивация:
    1. Отслеживание пути запроса
    2. Получение понимания на каком этапе мог провалиться запрос и почему
    3. Более полное представление о внутренних процессах

Предлагаемое решение:
    1. На первое время чтобы сразу начать получать и хранить логи можно настроить хранение логов через кликхаус, либо
    сразу внедрить решение ELK-стека.
    2. Для решения через кликхаус понадобиться только сам кликхаус и клиент для работы с логами.
    3. Логи будут передоваться в буферную таблицу в кликхаус и потом пачкой записываться в таблицу при необходимости
    могут быть заиспользованы функции агрегации для более экономного хранения логов.
    4. В дальнейшем можно будет перейти на ELK.
    5. Для метрик будет добавлен прометеус
    6. Для визуализации метрик будет использоваться графана так же будет добавлен конфиг с описанием сервисов
    которые надо опрашивать

Компромиссы:
    1. Необходимы временные и финансовые ресурсы для сервисов чтобы настроить логирование и хранить логи
    2. Необходимо просчитать какие логи как долго хранить
    3. Необходимо просчитать кол-во логов и доп нагрузку на сеть


Аспекты безопасности:
    1. Авторизация для пользователей
    2. Ролевой доступ
    3. Логирование действий пользователя
