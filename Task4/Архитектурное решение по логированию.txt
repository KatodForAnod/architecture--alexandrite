Какие логи нужно собирать (INFO, ERROR, FATAL) из всех систем:
    1. Логи о изменениях статуса заказа
    2. Логи о создании заказа
    3. Логи о непредсказуемом поведении
    4. Логи о всех действиях пользователя

Мотивация:
    1. Быстрое реагирование на инценденты
    2. Более полное понимание откуда возникла проблема

Системы в которые нужно впервую очередь внедрить логи:
    1. MES
    2. MES API
    3. Internet Shop

Предлагаемое решение:
    1. Использовать как хранилище логов КликХаус, так как он хорошо подходит для аналитических операций
    2. Для решения через кликхаус понадобиться только сам кликхаус и клиент для работы с логами.
    3. Логи будут передоваться в буферную таблицу в кликхаус и потом пачкой записываться в таблицу при необходимости
    могут быть заиспользованы функции агрегации для более экономного хранения логов.

Критерии:
    1. Доступ к логам должен быть доступен только для определенного круга лиц
    2. Логи info должны храниться не менее полугода
    3. Логи error, fatal должны храниться не менее года
    4. Размер логов не должен быть более 1ТБ

Аллертинг:
    1. Настроить метрики в графане на резкое увелечение логов Error
    2. Настроить метрики на ошибки при неудачной записи лога в бд

Критерии выбора кликхауса как хранилище логов:
Плюсы:
    1. Наиболее быстрое внедрение так как нужен только инстанс бд
    2. Гибкая настройка для ужимания логов через функции агрегации
    3. Быстрый поиск по данным
Минусы:
    1. В кликхаус для наилудшей производительности стоит записывать запросы пакетами
    2. Чтобы не терять скорость при записи можно использовать буферные таблицы
    3. Буферные таблицы являются ассинхроными, то есть запись в буф. тбл. не гарантирует запись в исходную таблицу
    4. Буферные таблицы храняться в ОЗУ
