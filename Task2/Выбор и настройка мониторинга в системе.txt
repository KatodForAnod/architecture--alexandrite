Мотивация внедрения мониторинга:
    1. Наблюдение за актуальным состоянием системы
    2. Настройка алертов и оперативное реагирование на инцеденты
    3. Обнаружение узких горлышек в системе

Выбор подхода к мониторингу:
    1. Для бд, хранилища файлов и очередей будет использоваться подход USE
    2. Для остальных приложений, АПИ будет использоваться подход RED

Метрики для приложений, АПИ:
    1. Кол-во запросов (юрл)
    2. Кол-во успешных запросов (юрл)
    3. Кол-во ошибочных запросов (юрл)
    4. Отношение ошибочных к успешным запросов
    5. Время ответа на запрос (Топ 5%) (Тип запроса, юрл)
    6. Размер запроса (Тип запроса, юрл)
    7. Размер ответа (юрл)

Метрики для бд, хранилища файлов и очередей:
    1. Загруженность процессора
    2. Загруженность ОЗУ
    3. Использование ПЗУ
    4. Размер свапа
    5. Кол-во подключений (для бд)

План действий:
    1. Установка прометеуса в приложениях
    2. Установка графана с конфигом как и какие сервисы опрашивать
    3. Вычисление пороговых значений для метрик
    4. Создание алертов с уведомлением на почту, телефон, корп. клиент
    5. При повышенной загрузке какого либо инстанса и наличия инструментов для масштабирование в ширину, увеличить
    кол-во инстансов. При отсутсвии таких инструментов, обеспечить масштабирование в высоту - добавить ресурсов.
